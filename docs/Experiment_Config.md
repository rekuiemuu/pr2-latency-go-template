# Конфигурация эксперимента

- Дата: 2026-09-15; ОС: Windows; реализация: Go 1.24.
- Адрес: loopback `127.0.0.1`; порты 19100–19105 соответственно сериям baseline, delay_50, delay_100, jitter, loss_5, combined.
- 50 PING в каждой серии; интервал 200 мс; тайм-аут 1000 мс; повторных передач нет.
- Эмулятор: встроенный режим Go-сервера из этого репозитория (не Clumsy), версия 1 (исходный код `cmd/server/main.go`). `-seed 42` для `math/rand`.
- baseline: без искусственной задержки; delay_50: 50 мс; delay_100: 100 мс.
- jitter: равномерный случайный выбор целой задержки 50–150 мс; combined: 100–200 мс.
- loss_5 и combined: сервер не отвечает на каждый 20-й PING. Это правило имитирует номинальные 5% на длинной серии; при 50 PING фактически пропускаются номера 20 и 40, то есть 4%.
- Сервер откладывает ответ в отдельной goroutine, поэтому задержка одного пакета не блокирует приём других.

Для воспроизведения последовательно запускайте сервер с `-mode <серия> -seed 42` и клиент с `-series <серия> -count 50 -interval 200ms`; для портов из исходного опыта добавьте `-addr` и `-server` соответственно. Смотрите [README](../README.md). Средние RTT меняются от загрузки ОС и планировщика, но правило потерь и seed фиксированы.
